# 運用ルール(業務OS)

## 1. ファイル命名規則

**形式**: `YYYYMMDD_施主名_書類種別_版.拡張子`

例:
- `20260629_ボノー様_資金計画書_v2.pdf`
- `20260620_前﨑様_発注書.pdf`
- `20260618_ボノー様_工程表.xlsx`

ルール:
- 日付は**作成日ではなく最終更新日**。更新したら日付を変えて別名保存(上書きしない)
- 旧版は案件フォルダ内の `old/` に移動する。**送付対象フォルダに版違いを2つ置かない**(誤添付の根本原因)
- 施主名の漢字は契約書表記に統一(領家/猟家、前﨑/前崎の混在禁止)

## 2. 案件フォルダ構成

```
案件/
  {施主名}様邸/
    01_契約/        (契約書・変更契約・資金計画書)
    02_設計/        (図面・仕様・見積)
    03_申請/        (太陽光・設備認定・行政)
    04_工程/        (工程表・発注書)
    05_引継メモ/     (顧客情報・打合せメモ)
    old/           (旧版の退避先)
```

## 3. 毎日のルーチン

| いつ | やること | 使うもの |
|---|---|---|
| 朝(5分) | Claude Codeで `/asa-brief` → 要返信・期限・予定を確認 | asa-brief |
| 朝(10分) | 要返信のうち定型のものは `/mail-draft` で下書き→確認→送信 | mail-draft |
| メール送信前(30秒) | 送信前チェック4点(宛先・添付・固有名詞・数字) | checklists.md |
| 週1回・金曜(10分) | `/kigen` で期限の棚卸し→カレンダー登録 | kigen |

## 4. AIに任せる範囲の線引き(安全ルール)

**AIがやってよいこと**:
- メール・カレンダー・Notion・Driveの読み取り、要約、検索
- Gmailの**下書き**作成
- チェックリストによる書類・見積のチェック(検出・指摘)
- 確認を取ったうえでのカレンダー登録・Notionページ追加

**AIがやってはいけないこと(必ず本人が実行)**:
- メールの送信
- 既存のファイル・Notionページ・予定の変更、削除
- 金額・発注・契約に関わる意思決定
- 顧客・業者への電話やLINE等での連絡
- パスワード・口座情報の入力や転記(パスワード通知メールの類はAIに触らせない)

**下書き運用の鉄則**:
- AIが作った下書きは「送信前チェック行」を消す作業を通じて必ず全文を読む
- 添付ファイルは本人が付け、開いて中身を確認してから送信する

## 5. Claudeセッションの使い方

- このリポジトリ(`oaua726/claude`)を開いてセッションを始めると、`.claude/skills/` のSkillが自動で使える
- 呼び出し例:
  - 「/asa-brief」または「朝ブリーフィングして」
  - 「/mail-draft インテルグローの綾部さんに◯◯様の見積確認の返信作って」
  - 「/kigen 直近3週間の期限まとめて」
  - 「checklists.md の見積チェックで、このPDFを確認して」(ファイルを渡す)
- 新しい定型作業が3回続いたら、それはSkill化のサイン。「この作業をSkillにして」と依頼する
