# POLYRUN

ブラウザで即遊べるローポリ無限ランナー。`index.html` 1ファイル完結（外部依存は three.js r128 の CDN のみ）。

## 遊び方

`games/polyrun/index.html` をブラウザで開くだけ。インストール不要、サーバー不要。

| 操作 | キーボード | タッチ |
|---|---|---|
| レーン移動 | ← → / A D | 左右スワイプ |
| ジャンプ | SPACE / ↑ / W | タップ・上スワイプ |
| スライド | ↓ / S | 下スワイプ |
| サウンド ON / OFF | M | 右下の SOUND ボタン（全画面で常時表示）|
| 一時停止 / 再開 | ESC・P（再開は SPACE / Enter も可）| 左下の PAUSE ボタン |

## ルール

- 3レーンの道を自動で前進する。障害物に1回でも当たったら終了。
- **赤い壁 → ジャンプ / 青いバー → スライド / 紫の柱 → レーン移動**。色で回避方法が決まる。
- クリスタルとニアミスでコンボが伸びる（最大 x10、3秒で切れる）。
- スコア = 距離(1/m) + クリスタル(10×コンボ) + ニアミス(25×コンボ) + ゾーン突破ボーナス。
- **400m で最初の切り替わり、以降 500m ごと**に SUNSET → NEON NIGHT → DAWN と景色が変わる（`biomeAt()`）。

## 特殊ゾーン（4種）

ランダムに発生してルールを一時的に書き換える。抜け切るとボーナス。
**最初の1回は約216m**で来る（生成の開始を 20m 地点に前倒し、初回間隔を 40m に短縮）。
以前は 655m で、多くのプレイヤーが一度も見ないまま終わっていた。初回だけ GAUNTLET を
除外しているので、最初に出会うゾーンは必ず「得をする側」になる。

| ゾーン | 効果 | ボーナス |
|---|---|---|
| LOW GRAVITY | 重力 45%・ジャンプ初速 80%。滞空が長くなり、クリスタルが高所に出る | +300 |
| CRYSTAL RUSH | 障害物が一切出ない。クリスタルの波でコンボを一気に積む | +250 |
| GAUNTLET | 障害物の間隔が 68%（下限 0.60秒）。ひたすら weaving | +450 |
| SPEED SURGE | 速度 1.3倍・距離スコア 2倍 | +350 |

障害物は **155m 手前で生成される**ため、ゾーンは「生成側」と「プレイヤー側」の2本のタイマーで
管理している。生成ルールを切り替えた 155m 後、その道がプレイヤーに届くのと同時にバナー・物理・
スコア倍率が発動する。分離しないと、バナーが出ている間ずっと前のルールの道を走ることになる。

LOW GRAVITY と GAUNTLET では**スライド用の障害物（青いバー）を出さない**。滞空が長い／間隔が
詰まった状態で「空中だと必ず当たる障害物」を混ぜると回避不能になるため、ジャンプで飛び越せる
赤い壁とレーン移動でかわす紫の柱だけに絞っている。

## OVERDRIVE（2,000m から先の難易度）

成長が止まる地点を実測したら、3つとも早すぎた。

| 要素 | 式 | 止まる地点 |
|---|---|---|
| 障害物の構成 | `d>110 / 220 / 420` で種類を追加 | **420m** |
| 列の間隔 | `max(0.80, 1.18 − d×0.00032)` 秒 | **1,187m** |
| 速度 | `min(46, 18 + d×0.0135)` m/s | **2,074m** |

3,811m まで走らせて確認した結果、**2,074m 以降のゲームは完全に同一**だった。
5km 走ることが 2km 走ることより難しくない＝上手い人には作業になる。

**間隔はもう下げられない。** ジャンプの滞空時間は `2×JUMP_V/|GRAV|` = **0.747秒**で、
列の間隔はすでに 0.80秒。ここを詰めると「ジャンプ直後にまたジャンプ」が
難しいのではなく**物理的に不可能**になる。だから動かせるのは残り2つ。

- **速度**：2,000m から 900m ごとに +1.4 m/s（上限 +14）。速度が上がると
  列の時間間隔は変わらないが、**155m 先に湧いた障害物を読める時間が縮む**
  （46m/s で 3.37秒 → 60m/s で 2.58秒）。判断を急がされるのはここ。
- **構成**：ティアが上がるほど `wlow` / `whigh`（全レーンをふさぐ）と `double` の
  比率を上げる。**横に逃げられる列が減り、正しい動作を選ぶしかなくなる。**
- **新しい列 `jumpslide`**：全レーンの壁 → 0.95秒後に全レーンの梁。
  ジャンプして、着地して、すぐスライド。滞空 0.747秒に対して 0.95秒なので
  **読む余裕が 0.2秒残る＝常にクリア可能**。間隔は調整値ではなく滞空時間から
  導いているので、速度がいくら上がっても不公平にならない。
- **報酬**：距離スコアがティアごとに **+25%**。深く潜るほど配点が跳ねるので、
  2km と 5km のスコアがはっきり分かれる。
- ティアに入った瞬間は `OVERDRIVE ×N` のバナーで告知し、以降は HUD の SCORE 横に
  `OD ×N` のチップを出す。**黙って難しくするとゲームが敵対的に見える**ので、
  何と引き換えかを必ず出す。
- SPEED SURGE 中は速度が 1.3 倍になり、置いたあとから `jumpslide` の間隔が
  縮んでしまうので、そのゾーンでは出さない。

7,613m まで走らせた実測：

| ティア | 到達距離 | 速度 | 逃げ道のない列の割合 |
|---|---|---|---|
| 0 | — | 18 → 46 m/s | 25%（設計値） |
| 1 | 2,000m | +1.4 | 36%（実測 39%） |
| 2 | 2,901m | +2.8 | 47%（実測 40%） |
| 3 | 3,800m | +4.2 | 53%（実測 62%） |
| 4 以降 | 4,701m〜 | +5.6〜+14 | 57%（構成の変化はここで頭打ち） |

`jumpslide` の壁→梁は 11 回すべて **0.950〜0.951秒**（滞空 0.747秒）。
式から出しているので速度が変わってもぶれない。

## デイリーミッション

- 日付（YYYYMMDD）をシードにした決定的な抽選で、**毎日3つ**のお題が出る。同じ日なら誰の端末でも同じ内容。
- お題は「1ラン単位」。ニアミス回数・距離・クリスタル・最大コンボ・スコア・ゾーン突破数の6種から
  易しい順に3つ選ばれる。
- 達成はリザルト画面で告知。3つ揃うと ALL CLEAR。

## バズり要素として入れたもの

- **ニアミス**：障害物をすれすれで抜けるとスローモーション＋ボーナス。切り抜きが映える瞬間を意図的に作っている。
- **リザルトカード**：1200×675 の PNG をその場で生成（Canvas 2D）。X にそのまま貼れるサイズ。`navigator.share` があればネイティブ共有、なければ画像長押し保存＋テキストコピー。
- **スマホ対応**：スワイプ操作、縦画面ではカメラを自動で引いて道幅を確保。
- **1プレイ 30〜60秒**：初見で理解でき、死因が常に自分のミスとして納得できる難易度カーブ。
- **特殊ゾーン**：1プレイの中身が毎回変わる。GAUNTLET や SPEED SURGE は切り抜きが作りやすい。
- **デイリーミッション／アンロック**：明日また開く理由と、長期の収集目標。

## 走り出しと自己ベスト

**出だしの空白を潰す** — 障害物は 155m 手前で生成されるため、素直に始めると
最初の1つが届くまで **10.8秒 / 194m** かかっていた。即リトライを作り込んでも、
その先に毎回11秒の空走がある状態だった。`seedWorld()` で走行開始時にコリドーを
あらかじめ埋め、**3.05秒 / 54m** で最初の障害物が来るようにした。あわせて開始速度を
少し上げている（`SPD_MIN` 17→18、イントロ係数 0.45→0.6、立ち上がり 1.3→1.8）。

**自己ベストを走行中の目標にする** — ベスト距離を `polyrun.bestDist` に保存し、
走行中のHUDに出す。100m手前で表示が金色に変わって脈打ち、予告音が鳴る。
超えた瞬間にスローモーション・フラッシュ・ファンファーレ・「NEW RECORD」バナーが出て、
以降は「RECORD +◯m」に切り替わる。**ルールは何も増えていない**が、これで全ての走行に
山場ができる。

## リトライ体験

ランナーゲームで一番効く中毒装置は「死んだ0.5秒後にもう走っていること」なので、そこを優先している。

- **即リトライ**：死亡演出中（0.28秒以降）に SPACE / Enter / R / タップでそのまま次の走行へ。
  リザルト画面を経由しなくていい。
- **走行結果は死亡した瞬間に確定**（`commitRun()`）。ベストスコア・累計スタッツ・デイリー達成・
  アンロック判定はすべてここで行うので、即リトライしても記録は一切失われない。
  リザルト画面（`renderResult()`）は表示専用。
- **シェア画像は遅延生成**。1200×675 の PNG は data URL で約1.1MB あり、以前は死ぬたびに
  必ず生成していた。いまはリザルト表示の 700ms 後に作り、リトライすればキャンセルされる。
  シェアを押したときは `ensureCard()` で即座に作ってから渡す。
- **死因を表示**。当たった障害物から `JUMP` / `SLIDE` / `DODGE` を判定する。
  あわせて「ベストまで あと ◯◯」も表示する。
- 助言の文面は**衝突した瞬間の状態から組み立てる**（`killCause()`）。障害物の種類だけで
  固定文を出すと、スライド中に赤い壁へ当たった人に「ジャンプで飛べた」と言うような、
  その瞬間には不可能だった操作を指示してしまう。判定しているのは次の4つ:
  - 空中だったか（`G.air`）— ジャンプ中はスライドできないし、紫の柱は跳び越せない
  - 上昇中か下降中か（`G.vy`）— 「ジャンプが遅かった」か「早かった」かが変わる
  - 直前にスライドを試みたか（押した時刻を記録。1フレーム遅れのスライドは `slideT` が
    十分上がる前に衝突するので、効果ではなく入力そのものを見る必要がある）
  - 隣のレーンが空いていたか（`laneWasFree()`）— 空いていればレーン移動も選択肢として出す

## 演出

走っている最中の情報量を、プレイの良し悪しに連動させている。

**コンボの段階変化** — `heat`（コンボ3〜8を 0→1 に正規化した値）が上がると、キツネに薄い残像が付き、
道路の縁のネオンが明るくなる。コンボが切れると `heat` は上がりの2倍の速さで抜けるので、
失った瞬間に画面から色が引く。残像は `rig` のクローン8体を使い回し、1体あたり不透明度の
書き換え1回で済むようにしている。

**ビート同期** — BGM は自前のシーケンサーなので、キックを鳴らす AudioContext 時刻が分かっている。
その時刻を `BEATS` に積み、描画側で `AC.currentTime` を追い越した分を取り出して脈を打たせる。
道路の縁・太陽・FOV がキックに合わせて動く。**減衰を先に掛けてから取り出す**のが要点で、逆順だと
取り出した直後にそのフレーム分の減衰が掛かり、ピーク値がフレームレート依存になる（24fps で 0.83、
60fps で 0.92）。

**ジャンプと着地の重み** — 離陸で縦に伸び、着地で落下速度に比例して潰れる（スクワッシュ&ストレッチ）。
着地時には路面に広がるダストリング、カメラの沈み込み、落下速度でボリュームが変わる着地音が出る。

**アクロバットジャンプ** — 速度が上がるとジャンプが宙返りになる。約330m（`sn>=0.16`）で1回転、
最高速域（`sn>=0.75`）または滞空1.05秒超（低重力ゾーン）で2回転。脚を畳み、尻尾を伸ばした
タック姿勢を取る。

回転は**残り滞空時間から毎フレーム再計算**している（`tR=(vy+√(vy²+2g·py))/g` で着地までの
時間を解き、残り回転量をそれで割って角速度を出す）。単純に離陸時の滞空時間で割ると、
空中で↓を押して急降下したときに回り切らず**横倒しで着地**してしまう。再計算方式なら
急降下しただけ速く回るので、何をしても必ず直立で着地する。

## 一時停止

- 走行中のみ有効。ESC / P / 左下の PAUSE ボタンで停止し、RESUME・最初からやり直す・
  タイトルへ の3択。停止中はスコアと距離を表示する。
- **タブを離れると自動で停止する**（`visibilitychange` と `blur`）。裏に回っている間に
  死ぬことがない。復帰時は自動再開せず、本人の操作を待つ。
- **再開は 3・2・1 のカウントダウンを挟む**。押した瞬間に走り出すと、目を離していた分だけ
  理不尽に死ぬため。カウント中も世界は止まったまま。
- BGM は `hold()` / `unhold()` で止めて戻す。`step` を保持したままスケジューラだけ止めるので、
  再開時にループの途中から続く（`start()` は先頭に巻き戻るので使わない）。
- 実装上は `state='pause'` で `step()` の先頭から抜けるため、物理・生成・スコアが一切進まない。

## 言語（日本語 / English）

ゲーム本体は言葉を必要としないのに、**ラベルが全部日本語だったせいで届く相手が
日本語を読める人に限られていた**。文言をすべて `I18N` にまとめ、日本語と英語を
その場で切り替えられるようにした。

- 初回は `navigator.language` で判定する。`ja` で始まれば日本語、それ以外は英語。
  以降は `polyrun.lang` に保存した選択を優先する。
- 右下の言語ボタン（`日本語` / `English`）でいつでも切り替わる。押した瞬間に
  タイトル・ミッション・キツネの解放条件・TIP まで作り直すので、再読み込みは要らない。
  走行中だけは隠す（PAUSE ボタンと入れ替わる）。
- 静的な文字列は HTML 側に `data-i18n` / `data-i18n-html` / `data-i18n-alt` を書き、
  `applyLang()` が一括で流し込む。動的に組み立てる文字列は `t('key', 値…)` を通す。
  `{0}` 形式のプレースホルダなので、**語順が日本語と英語で逆になる文でも差し替えられる**
  （例: `'{0}はジャンプで飛び越す{1}'` / `'Jump over {0}{1}'`）。
- 死因アドバイス・ゾーン説明・ランク名・共有テキスト・トーストも含めて全文を用意した。
  英語側の障害物名は `the red wall` のように冠詞込みにして、文に埋めたときに自然に読めるようにしている。
- 一時停止の見出しだけは、日本語のときに `jp-title`（Zen Kaku Gothic New）、
  英語のときに `disp`（Bungee）へ切り替える。ワードマーク用の字形は日本語を持っていないため。
- キーが欠けた場合は英語にフォールバックし、それも無ければキー名をそのまま出す。

## フレームレート非依存の当たり判定

当たり判定は「障害物の z が ±(奥行き/2 + 0.55) の窓に入った瞬間」で取っている。窓の幅は約
**1.82m** しかないのに、1フレームの前進量は `速度 × dt`（dt は 0.05秒で頭打ち）で、
top speed の 46m/s では **2.30m**、SPEED SURGE 中の 59.8m/s では **2.99m** になる。
つまり **20fps を割る端末では、障害物が窓をまたいで一度も判定されずに通り過ぎていた**。

- 壁をすり抜けて生き延びることがあり、同じ窓でニアミスも見ているので、
  低スペック端末は**加点も黙って取りこぼしていた**。
- 対策は判定側ではなく**世界の進め方**を変えること。`frame()` で 1 フレームを
  `SUBSTEP=0.02` 秒以下のスライスに割り、`step()` をその回数だけ呼ぶ。
  1スライスの前進量は最悪でも 59.8 × 0.02 = **1.20m** で、窓の 1.82m を超えない。
- 60fps では `ceil(0.0167/0.02)=1` なので **従来と完全に同じ1回呼び出し**。
  分割が走るのは 50fps を下回ったときだけで、そのぶん物理の積分精度も上がる。
- 実測（CPU を 1/4・1/8 に絞って各25秒）: 修正前は窓を飛び越えた障害物が 2件・5件、
  修正後は **どちらも 0件**。

## 読み込み中の表示と言語モジュール

文言を `applyLang()` で流し込むようにした結果、**three.js（約600KB）を待つ間、
タイトルの説明文が空っぽ**になっていた。さらに three.js が届かなかったときは
`typeof THREE==='undefined'` の早期 return が言語処理より前にあるため、
**WebGL 失敗画面の本文まで空欄**で表示されていた。

- 言語モジュールを `<script src=three.js>` の**前**の独立した `<script>` に切り出し、
  `window.PolyLang` として公開する。本体スクリプトは `W.PolyLang` から `t` を受け取る。
- これで文言は three.js のダウンロードを待たずに出るようになり、
  three.js が一度も届かない場合でも失敗画面が自分の言葉で説明できる。
  言語ボタンも失敗画面で生きたまま。
- 一覧を組み直す処理（ミッション・キツネ・TIP）は本体側にしか無いので、
  `boot()` で `LANG.onChange(...)` に登録してから呼ばれるようにした。

## ループのエラーを握り潰さない

`frame()` の `try{ step(raw); }catch(e){}` は catch が空で、**step が例外を投げると
画面が固まるだけでコンソールに何も残らなかった**。1フレームの失敗でループごと
止めたくはないので try は残しつつ、初回だけ `console.error` に出すようにした。
（検証スクリプトが `pageerror` を拾えず「エラーなし」と誤報告する原因でもあった。）

## 入力バッファ

空中でのジャンプ／スライド入力を短時間保持し、着地した瞬間に消化する。

- ジャンプ 0.15秒、スライド 0.17秒。
- これが無いと「着地の100ms前に押したジャンプ」が黙って消え、ゲームに無視されたように感じる。
- バッファは時間制限付きなので、頂点付近で押した入力は着地前に失効する（勝手に跳び続けない）。

## 実装メモ

- three.js r128（UMD / cdnjs）。マテリアルは `MeshPhongMaterial({flatShading:true})` で統一。
- 道路と地面はスクロールする **Canvas 2D 生成テクスチャ** 1枚ずつ。ジオメトリは各2三角形で、無限に続く道をほぼゼロコストで描いている。
- 障害物・クリスタル・ビル・パーティクルはすべてプール再利用（`Pool`）。実行中の new は発生しない。
- **ビルは4種のシルエット**（板／セットバック／尖塔／看板付き）を、同じ6つの子メッシュの
  表示・非表示と変形だけで作り分ける。生成のたびに組み直さないので、尖塔でも板と同じコスト。
  - 窓は1枚のキャンバス（一部の窓をランダムに消灯）をビルごとに `clone()` して
    `emissiveMap` に使い、`repeat` を大きさに比例させて窓のサイズを揃えている。
    バイオームごとの `win` 色を `emissive` に入れるので、夜だけ強く光る。
  - 看板は屋上ビルボードと壁から突き出す縦看板の2種。**壁と平行に貼ると通り過ぎる一瞬しか
    見えない**ため、どちらも道路側へ少し振っている。
  - 尖塔の頂点の航空障害灯は全ビルで1枚のマテリアルを共有し、BGMの小節頭で明滅させる。
  - ビルの本数は増やしていない。本数を増やすとモバイルのフレームレートが目に見えて落ちる
    （実測で約12%）のに対し、シルエットの作り分けはほぼ無料。
- 当たり判定は軸ごとの「クリアランス」で計算し、`max(横のクリア, 縦のクリア)` が 0〜0.52 の範囲ならニアミス扱い。スライド高さは連続値で補間しているので、スライドが遅いほど判定がギリギリになる。
- ニアミスは**残り幅で3段階**に評価する（`NM_TIERS`）。PERFECT（0.18未満・2.0倍）/
  GREAT（0.33未満・1.5倍）/ NICE（0.52未満・等倍）。段階ごとにスロー・シェイク・
  ポップの大きさも変える。放置ボットでの計測でニアミスがスコアの0%だったため、
  **HUDに回数を常時表示**し、**初回のニアミスで一度だけ**解説を出すようにした
  （`polyrun.taughtNear` に記録して二度目は出さない）。
- **BGM・効果音とも WebAudio で合成。音声ファイルは1つも持たない**＝実況・配信で権利の問題が出ない。
  BGM は Am - F - C - G / 124BPM の4小節ループを16分音符ごとにスケジュールして鳴らしている
  （パッド・ベース・キック・ハイハット・アルペジオ＋ディレイ）。走行速度に連動して
  `inten` が上がり、フィルターが開いてドラムとアルペジオが乗る。
- 音声グラフは `sfx -> out -> destination` / `bgm -> out -> destination` の1本。
  ミュートは `out` のゲインを 0 にするので、**再生中の音も含めて即座に止まる**。
- 保存は localStorage の `polyrun.*`（`best` / `muted` / `prof` / `daily` / `lang`）。読み書きは try/catch で保護。
- `prefers-reduced-motion` で画面シェイク・スローモーション・パーティクル量を抑制。
