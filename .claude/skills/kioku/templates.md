# 記録テンプレート

セッション記録DBの1行に書く本文の型。**該当なしの項目は行ごと省く。**

共通の鉄則: **田中さんの発言(指示・訂正・好み)は原文のまま引用する。**
要約も整形もしない。言い回しとニュアンスがそのまま文体・判断基準の資産になる。
Claudeの作業内容は要約でよい。

---

## 種別 = 指示

```markdown
**田中さんの指示(原文)**

> （そのまま引用）

**受け取った内容**
- 何をすることになったか

**前提・制約**
- 
```

---

## 種別 = 決定

```markdown
**田中さんの指示(原文)**

> （そのまま引用。指示が起点でない場合は省く）

**決めたこと**
- 一文で

**なぜそう決めたか**
- 

**却下した案**
- 案 — 却下理由

**恒久ルールか**
- 恒久 / 今回だけの単発判断

**関連**
- 
```

恒久ルールになったものは `重要度=高`。`docs/unyo-rule.md` への反映も提案する。

---

## 種別 = ミス

`対応状況=未対策` で作る。謝罪文ではなく再発防止の材料として書く。

```markdown
**指摘(原文)**

> （田中さんの指摘をそのまま引用）

**何をしたか(実際の誤った行動)**
- 

**本来どうすべきだったか(正しい対処法)**
- 

**なぜ間違えたか**
- 思い込み / 確認不足 / ルール未読 / 指示の読み違い のどれか

**再発防止チェック**
> 次に同じ状況になったら、自分にこう問う:「　」

**ルール側の修正**
- 必要 / 不要(必要なら何をどう直すか)
```

対策が定着したら `対応状況=対策済み` に更新し、本文末に `(YYYY-MM-DD 対策済み: 〜)` を追記する。
**行も記述も消さない。**

---

## 種別 = 好み・文体

最も価値が高い記録。**原文の引用を必ず入れる。**

```markdown
**発言(原文)**

> （そのまま引用）

**読み取れる好み**
- 

**適用範囲**
- メール文面 / 報告の書き方 / 判断の仕方 など

**出典**
- いつの、何の作業中か
```

---

## 種別 = ナレッジ

```markdown
**何が起きたか / 何をしたいか**
- 

**原因・前提**
- 

**手順(そのまま再現できる粒度で)**
1. 
2. 

**ハマりどころ**
- 
```

DBの1行では収まらない、繰り返し参照するまとまった知識になったら、
Knowledgeページへ「〜の原則」「〜のやり方」形式で転記し、DB側から参照を張る。

---

## 種別 = 事実

```markdown
**事実**
- 判明した制約・仕様・相手の事情

**だからどうするか**
- 

**出典**
- どこで分かったか
```

---

## 種別 = 作業

```markdown
**やったこと**
- 

**結果**
- 

**次にやること**
- [ ] 
```

セッション終了時の引き継ぎもこの種別で作る。

```markdown
**次回への引き継ぎ**
- 前提:
- 未確定:
- 触ってはいけないもの:
```
